What The Crewmate Bot Does

The crewmate AI bot is a Discord bot for the Modded Among Us Lobbies community. It is designed to act like a silly Among Us crewmate friend, answer MAUL support-style questions, remember harmless preferences users choose to save, and build a configurable friendship-style experience.

The bot is not intended to replace staff decisions, moderation judgment, or official announcements. If a question is account-specific, moderation-related, ban-related, or unclear, the bot should direct the user to the correct support or ticket route.

Information The Bot May Store

User profile and preference data

  • Discord user ID and server ID, used to attach bot settings to the correct user and server.
  • Optional nickname, favorite color, preferred crewmate color, personality setting, and harmless preferences.
  • Optional friendship score or relationship-style game progress calculated by bot code.
  • Explicit memories users save with memory commands.

Conversation and support data

  • Short recent conversation context may be used so replies make sense.
  • Staff-taught support facts may be stored with the staff member ID, source message ID, category, title, body, and timestamps.
  • Command usage, cooldowns, safety events, and basic logs may be stored to keep the bot working and prevent abuse.
The bot should not silently build psychological profiles, infer protected traits, or store sensitive personal information from ordinary server chat.

How AI Responses Work

When a user talks to the bot, the bot may send the user's message, a small amount of recent context, selected explicit memories, and relevant support knowledge to the OpenAI API so a response can be generated.

  • Discord messages are not used to train or fine-tune AI models for this bot.
  • The bot should use OpenAI API settings such as store: false where supported.
  • The bot should only send information needed for the requested response.
  • The bot should not send full server history or unrelated channel history to the AI provider.

AI responses can be wrong. Users should treat the bot as a helpful crewmate, not an official final source for moderation decisions, policy exceptions, or private staff matters.

User Memory

The bot may remember users only through explicit memory and profile features. These memories are stored by the bot so it can feel more personal without needing to train on Discord messages.

Allowed memory examples

  • "My favorite crewmate color is cyan."
  • "Call me Sarha."
  • "Use chaotic personality mode with me."
  • "Do not joke about this topic with me."

User controls

  • /memories should show saved memories.
  • /forget should remove a selected memory.
  • /forgetme should wipe bot-specific user profile and memory data where eligible.
  • /data should explain or export what the bot stores about the user.

Staff Teaching And Support Knowledge

Approved support users may teach the bot server facts, setup instructions, event notes, or support answers. This is stored as a bot knowledge base, not as model training.

  • Support role ID allowed to teach: 1115553042150981686.
  • Teaching can be done through a command such as /teach or a staff-approved teach message.
  • Taught facts should be searchable, editable, expirable, and deletable by approved staff.
  • Event facts should be treated as time-sensitive and not presented as current forever.

Mentions, Pings, And Safety Limits

Generated bot messages should not be able to mass ping the server.

  • The bot should never ping roles, @everyone, or @here.
  • The bot should not mention more than two users in one generated response.
  • Generated output should be sanitized before sending.
  • Discord allowed_mentions should be set to suppress unsafe mentions by default.

Server And User Controls

User controls

  • Users should be able to view, reset, or delete their bot-specific memory data.
  • Users should be able to choose personality settings and opt out of memory-style personalization.
  • Users can avoid the bot by not mentioning it or using its commands.

Server controls

  • Admins should be able to choose enabled channels.
  • Admins should be able to control spontaneous messages, reactions, cooldowns, and AI features.
  • Admins should have access to an AI kill switch if the feature needs to be disabled quickly.

Retention And Deletion

Bot data should be kept only as long as needed for the feature it supports, safety, abuse prevention, troubleshooting, or server administration. Eligible user profile and memory data should be deleted when a user uses deletion commands or contacts staff with a valid request.

Some limited records may be retained when needed for security, abuse prevention, audit logs, unresolved disputes, or legal/compliance reasons.

Contact

For privacy questions, data requests, or concerns about the crewmate AI bot, contact the MAUL owner or use the support route provided in the Discord server.
